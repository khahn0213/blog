Firestore로 블로그 조회수를
비싸지 않게 세는 방법

2026년 9월 12일 · 12분 읽기 · 조회 1,284

조회수는 블로그에서 제일 단순해 보이는 기능인데, 그대로 구현하면 문서 쓰기 비용이 방문자 수만큼 늘어납니다. 며칠 굴려보며 정리한 방법을 남깁니다.

문제는 쓰기 횟수였다

페이지가 열릴 때마다 게시글 문서의 views 필드를 1 증가시키는 방식은 구현이 가장 쉽습니다. 다만 같은 문서에 초당 한 번 이상 쓰기가 몰리면 경합이 생기고, 트래픽이 조금만 늘어도 쓰기 과금이 읽기 과금을 앞지릅니다.

한 문서에 대한 쓰기는 초당 1회가 권장 한계입니다. 인기 글 하나가 이 한계를 넘기면 나머지 요청이 줄을 서기 시작합니다.

분산 카운터와 배치 집계

해결책은 두 단계로 나눕니다. 방문 시점에는 이벤트만 얕게 적고, 집계는 하루 한 번 몰아서 합니다.

const shard = Math.floor(Math.random() * 10);
await setDoc(
  doc(db, `posts/${slug}/shards/${shard}`),
  { count: increment(1) },
  { merge: true }
);

샤드를 10개로 쪼개면 같은 문서에 몰리던 쓰기가 나뉘고, 조회 화면에서는 샤드 합계를 한 번만 읽어 캐시합니다. 실제 지표 분석은 GA4 쪽에 맡기고 Firestore에는 표시용 숫자만 두는 편이 비용과 복잡도 모두 낮았습니다.

남은 과제

지금은 샤드 합계를 방문할 때마다 다시 읽고 있는데, 인기 글 상세는 5분 캐시를 둬서 읽기도 더 줄일 수 있을 것 같습니다. 다음 글에서 이어서 정리하겠습니다.
